Archive UI drafts

Four directions for replacing the vendored CharacterLibrary frontend. All three run on 98 real cards from data/characters with real thumbnails, so density and text overflow are honest. Static HTML only — the target stack is React 19 + Vite + Tailwind + shadcn, same as cbz-tagger.

Draft D · current direction

Archive

C's full-page detail route and clean section bar, B's sage palette, four tabs, and no infinite shelves. This is the one to react to — A/B/C below are the originals it was fused from.

  • Tabs: Characters · Favorites · Discover · Tags
  • One optional "Recently added" row, clipped to exactly one grid row
  • One chip strip for tags + filters, understated Sort, no density control
  • Tags tab is the consolidation editor (canonicals, merged variants, staged apply)
  • Activity popover, Import menu, and a full Settings route
 Draft A

Rail

Icon rail, one command bar, dense poster grid, detail as a right-side sheet that keeps the grid visible.

  • ⌘K command palette replaces the "More options" menu
  • Filters live as chips in a strip
  • Keyboard J/K through the sheet
 Draft B

Workbench

Faceted sidebar, grid, docked inspector. No modals anywhere; the inspector doubles as a collection dashboard and bulk editor.

  • Tag/creator/source facets with live counts
  • ⌘-click multi-select → bulk edit panel
  • Light and dark
 Draft C

Shelves

Cinematic browse: hero, horizontal shelves, and a full-page detail route instead of a cramped modal.

  • Shelves encode real queries (recent, deep lorebooks, never opened)
  • Search as a full overlay
  • Detail is a URL you can link to

Open any file directly in a browser, or python3 -m http.server from this folder. Card data is baked into cards-data.js (1.3 MB of base64 thumbnails) — mock-only, not shipped.
